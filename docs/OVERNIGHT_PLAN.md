# 8시간 야간 작업 계획 (가치망 개선 + 정보 실험 + 엔진 스윕)

목표: 지금 가치망(v2)은 탐색 깊이/데이터를 늘려도 승률이 안 올랐다. 원인은 학습 라벨이 '휴리스틱 롤아웃 평균'이라 휴리스틱 수준을 못 넘는 것이다. 라벨을 '탐색 결과'로 바꿔 가며 반복 개선(부트스트랩)하고, 그 위에서 정보 가치 실험과 엔진 스윕을 돈다.

원칙: 워커 4개 이하 / GPU는 학습에만 / 각 단계 결과는 `verify/out/night_*.log` 와 `docs/PROGRESS_AI.md` 에 기록 / 로컬 커밋만(푸시 안 함) / 새 모델이 기존보다 나쁘면 기존 모델 유지.

## 단계별 상세

1. **부트스트랩 라벨 생성** (핵심)
   - 입력: 기존 `data/value_v2` 의 상태 중 서로 다른 팀/턴이 고르게 섞이도록 10만 개 샘플.
   - 각 상태에서 `payoff_matrix_value`(v2 로 한 턴 뒤 가치) → `solve_zero_sum` → 게임 값 v. 숨은 정보 없이 실제 상대 세트로 계산(정답 라벨 용도).
   - 비용 추정: 상태당 행동 쌍 약 30개 x 표본 2 = 60번 엔진 한 턴 진행 → 상태당 0.1~0.2초 → 워커 4개로 10만 개 약 80~90분.
2. **재학습**: 같은 구조(ValueNet), 라벨 혼합(부트스트랩 70% + 결과 30%), 14 에폭, 검증은 팀 단위 분할. 검증 logloss 가 v2 보다 나쁘면 폐기.
3. **평가**: 기존 설정과 동일(세계 3 x 롤아웃 4, pick=max). 같은 시드 2000+g, 양쪽 자리 번갈아. 이전 결과(v2: flat 상대 55.9%, v3: 48.6%)와 비교.
4. **숨은 정보 실험**: 지금 탐색(nashv)에서 정보를 단계별로 알려 줬을 때의 승률 차. 추론기 개선 우선순위의 근거가 된다.
5. **엔진 스윕은 이번 밤에는 생략**(CPU 경쟁). 아침에 따로 한 번 돌린다.

## 성공 기준 / 실패 시 행동
- 성공: nashv(v3b 또는 v3c) 가 nashv(v2) 를 오차 범위 밖(55% 이상)으로 이김.
- 중간: 동률이면 가치망 구조/라벨 혼합 비율을 바꿔 아침에 재시도(원인 분석 기록).
- 실패(오히려 나빠짐): 기존 v2 유지, 라벨 노이즈(1턴 탐색 + 가치망 오차 누적) 가능성을 기록하고 탐색 라벨을 2턴으로 늘리는 방안을 아침 과제로 남긴다.

## 위험 요소
- CPU 온도: 워커 4개 유지, 하드웨어 보호는 믿되 20분마다 로그로 진행 확인.
- 디스크: 부트스트랩 데이터 약 2~3GB 예상 (여유 확인 필요).
- 엔진 버그가 라벨에 섞일 가능성: 시작 전 회귀 0건을 조건으로 한다.
